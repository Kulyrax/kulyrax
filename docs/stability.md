# Stability (draft)

**Status: draft for the 1.0 plan, step 1.** This page lists everything that would
become a compatibility promise at 1.0.0, and proposes for each item one of:

- **FREEZE**: kept as it is and covered by semver from 1.0.
- **CHANGE**: changed before 1.0 (the step that changes it is named), then frozen.
- **UNSTABLE**: kept but outside the promise (`#[doc(hidden)]` or documented as
  unstable), or made private (`pub(crate)`).

Nothing here is decided until the owner approves it. Inventory taken at `d80b3cd`
(0.12.0).

## 2. YAML

### Config (`config.yaml`)

| Key | Notes | Proposal |
|---|---|---|
| `version` | **already required**, must be `1` (`KulyraxConfig::validate`) | **FREEZE**. Step 5's "add `version: 1`, missing means 1" would loosen a check that exists; see §9 |
| `routing.file` | path, relative to the config | FREEZE |
| `adapters[]`: `type`, `id`, `priority`, `capabilities` (`write`, `idempotent`, `upsert`, `transactions`, `delete`), `depends_on`, `config` | built-in types `sqlite` (`path`), `file` (`root`), `keyvalue` (`root`), `graph` (`root`); registered types `postgres` (`url`, `pool_size`), `mysql` (`url`, `pool_size`), `redis` (`url`, `pool_size`), `mongodb` (`url`, `database`, `pool_size`), `neo4j` (`uri`, `user`, `password`, `database`), `elasticsearch` (`url`, `username`, `password`, `timeout_ms`) | FREEZE; `${ENV}` expansion in `url` / `password` FREEZE |
| `failure_policy` | `fail_fast` (default), `continue_on_error` | FREEZE |
| `migration_policy` | `strict` (default), `ignore_unmatched` | FREEZE |
| `sources[]` | `directory` (`id`, `path`, `state_dir`), `stdin` (`id`, `state_dir`), `postgres_outbox` (`id`, `state_dir`, `config`: `url`, `table`, `sequence_column`, `columns.{event_id,event_type,payload,metadata,version}`, `gap_grace_ms`, `gap_timeout_ms`, `watch_retention_ms`, `allow_unverified_sequence`) | FREEZE |

Unknown keys: no built-in config or mapping struct rejects unknown keys (no
`deny_unknown_fields` in `runtime/config.rs` or any `mapping.rs`), so a misspelt key
is silently ignored; `OutboxConfig` rejects them. **CHANGE** (step 5 or 4): pick one
rule for all; rejecting is the safer one to freeze, and the breaking one to adopt.

### Mappings (`mappings/{sql,document,keyvalue,graph}/*.yaml`, `version: <n>`)

`version` here is the **target payload schema version** (for upcasting), not a
file-format version: a mapping file has no format version of its own.

| Kind | Keys | Proposal |
|---|---|---|
| SQL | `event`, `table`, `version`, `primary_key` (one or many), `columns`, `on_existing` (`ignore` / `replace`), `operation` (`upsert` / `delete`), `permanent`, `facet`, `requires_capabilities` | FREEZE |
| Document | `event`, `collection`, `version`, `id`, `document`, `on_existing`, `operation`, `permanent`, `facet`, `requires_capabilities` | FREEZE |
| Key-value | `event`, `namespace`, `version`, `key`, `value`, … same tail | FREEZE |
| Graph | `kind: node` (`label`, `key`, `properties`, `facet`), `kind: edge` (`edge_type`, `from`, `to`, `discriminator`, `properties`), `kind: subgraph` (`event`, `version`, `records`) | FREEZE |
| Path expressions | `payload.<field>`, `metadata.<field>` | FREEZE |

### Routing (`routing.yaml`)

`EventType: [adapter-id, …]`. **FREEZE**.

All YAML is parsed by `serde_yaml` (YAML 1.1 rules); step 3 replaces it, and any
parsing difference is decided there.

## 7. Findings

- **F1, a correctness bug in the file key-value store** (verified with a throwaway
  test, not committed): guards live at `.conduit/<namespace>/…`, beside the file
  store's own `wal/` and `lock`.
  - A namespace named **`wal`**: after a restart the store believes it is empty
    (`store_is_empty` ignores `wal`), reads no guard from disk, and an older,
    redelivered event is **`Created`** over the newer value (a namespace `users`
    gives `Skipped(StaleSequence)`).
  - A namespace named **`lock`**: every write fails (`os error 183`, `lock` is a
    file).
  Proposal: fix in step 2, since the rename moves this tree anyway: key-value
  guards under their own subdirectory (`.kulyrax/kv/<ns>/…`), and reserved names
  refused at validation.
- **F2**: the config file already has a required `version: 1` (§2).
- **F3**: v0.11.0 was never tagged, and `CHANGELOG.md` stops at v0.10.0.
- **F4**: error types flatten their causes into strings; a `source()` chain (step 4)
  means changing those variants, which is itself an API change.

## 9. Questions for the owner

1. **LICENSE copyright holder**: "Conduit Contributors" → "Kulyrax Contributors"?
2. **Config `version`**: it is already required. Keep it required (proposed), or let
   a missing `version` mean 1 with a warning as step 5 says?
3. **Generated gRPC code** (`pb` in `kulyrax-ingest` / `kulyrax-client`): freeze it
   (semver then follows tonic/prost), or hide it behind Kulyrax types?
4. **Adapter `new` constructors**: hide them (proposed), or freeze them?
5. **Exit codes**: keep `0`/`1`, or split configuration errors from event failures
   before freezing?
6. **`Event`**: `#[non_exhaustive]` stops embedders from building it with a struct
   literal, which every test and example does. Freeze it exhaustive (proposed), or
   add a constructor and mark it non-exhaustive?

# Kulyrax v0.6.0

## Status

Alpha — feature release covering **Phases 11–17**, plus Phase 18 consolidation/hygiene.

This release turns the projection engine from "idempotent by `event_id`" into "entity-keyed, sequence-gated, crash-resumable", adds two storage adapters and a source abstraction, and closes the **effectively-once projection** guarantee.

---

## Highlights

### Entity-aware, sequence-gated idempotency (Phases 11–13)
- Idempotency is now keyed by **entity** (`primary_key` / `id` / `key`), not `event_id`. A redelivered creation with a fresh `event_id` for the same entity is skipped, not duplicated.
- One shared pure function, `decide()` (`adapter/mod.rs`), gates every adapter's write: `Insert` / `Update` / `Delete` / a skip variant, from the `Operation`, the mapping's `on_existing`, the guard lane state, and `event.sequence`.
- `on_existing: replace` → sequence-gated overwrite; `operation: delete` → tombstone; `permanent: true` → terminal tombstone; a newer `upsert` on a non-permanent tombstone resurrects (Phase 13.4).

### Facet partial updates (Phase 15)
- An event can update a **named subset** of an entity's columns/keys — one facet — on its own sequence lane, so independent event streams touching disjoint fields never falsely supersede each other.

### Key-Value adapter (Phase 14) and Graph adapter (Phase 16)
- All four storage kinds from the project pitch now exist (file-backed): SQL, Document, Key-Value, Graph.
- Graph: nodes and edges as separately-keyed `decide()` lanes; `operation: delete` on a node is a `DETACH DELETE`.

### Event sources & the run loop (Phase 17)
- New `EventSource` trait + `directory` / `stdin` sources, config-declared under `sources:`.
- `kulyrax run` is a `poll → sort → dispatch → commit` loop; `--once` drains and exits (subsumes `replay`). Checkpoints resume across restarts.
- **Effectively-once projection:** at-least-once redelivery + sequence-gated idempotent sinks + commit-after-batch ⇒ the state after any crash/restart/redelivery equals a single clean pass.

## Behaviour changes — read before upgrading from v0.5.0-alpha

### Guard table replaced and its schema changed
- The Phase 4 `kulyrax_events` (event-id) guard table is **superseded** by `conduit_projection_state`
  (`target_table, entity_key, facet, last_sequence, last_event_id, deleted, permanent, processed_at`,
  PK `(target_table, entity_key, facet)`).
- The schema gained `deleted` / `permanent` (Phase 13) and the `facet` PK column (Phase 15).
- **There is no in-place migration.** A guard table from before this release must be **dropped**; it is a derived cache and `kulyrax run --once` (or `replay`) rebuilds it. The 3-column `ON CONFLICT` target cannot be satisfied by an older constraint.

### Document / KV / graph guard sidecars
- Format extended with a `facets` map (Phase 15) and `deleted` / `permanent` (Phase 13). The **default facet stays in the flat fields**, so a pre-Phase-15 sidecar for a non-faceted entity round-trips unchanged.

### Document output path re-keyed
- Entity files and guards are now keyed by `(collection, entity_id)` (Phase 13.3), not `(event_type, entity_id)`. A `delete` event has a different `event_type` than its `create` but the same `collection`, so it now targets the right file. This is a behaviour change to Phase 3/4 output layout: `{collection}/{id}.json`, not `{event_type}/{id}.json`.

### `Event.sequence` is required and load-bearing
- Present since Phase 11; used for **gating** (Phase 12) and **ordering** (replay and the source loop stable-sort by it — Phase 15.5). It must be monotonically increasing for successive events of one entity. It is **not** the timestamp and is **unrelated** to `version` (schema version). See [`docs/producer-contract.md`](../docs/producer-contract.md).

### Execution report JSON shape
- `AdapterOutcome` (`created` / `updated` / `deleted` / `skipped` + `reason` / `failed`) **replaced** the old `success: bool` + skip-message encoding (Phase 12.1).
- `SkipReason` is machine-readable: `already_projected`, `stale_sequence`, `already_deleted`, `tombstoned`, `entity_absent`, `unsupported_version`.
- `ExecutionReport` gained `source_id` / `source_position` (Phase 17), `source_version` / per-adapter `projected_version` (Phase 10). All additive (`Option`, `#[serde(default)]`).

### Config
- New optional `sources: []` block (`directory` / `stdin`). Duplicate source ids are rejected at startup.
- `<mappings_dir>/keyvalue` and `<mappings_dir>/graph` are **optional** directories (unlike the mandatory `sql/` and `document/`).

### CLI
- `kulyrax run` gained `--once`, `--max-batch`, `--poll-interval-ms`, `--dlq`. Without `--event` it runs the source loop; a Ctrl-C finishes the in-flight batch, commits, and exits.
- New `kulyrax sources` command.
- `kulyrax replay` is unchanged but superseded by `kulyrax run --once`.

### Internal API (library callers)
- `execute_event*`, `ReplayContext::new*`, `replay_stream*`, `validate_projection_config`, `build_adapters_from_config` gained `kv_mappings` (Phase 14) and `graph_mappings` (Phase 16) parameters. Front ends going through `kulyrax_core::pipeline` are unaffected.

- Deleted the dead `adapter/sql/validate.rs` and `adapter/document/validate.rs` (pre-Phase-8, unreachable; live validation is `runtime/validation.rs`).

---

## Non-Goals (unchanged)

- No exactly-once *delivery*, no Kafka/broker source, no event store.
- No distributed/multi-instance coordination.
- No backpressure or rate limiting.
- No backward-compatibility guarantees between alpha releases.

Not intended for production use.

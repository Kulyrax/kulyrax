# Kulyrax v0.12.0 (draft)

## Status

Alpha. This release adds a **Postgres outbox source** and the **source registry**
that third-party sources plug into. It contains small **breaking changes** for code
that embeds `kulyrax-core`; see [Upgrading from 0.11](#upgrading-from-011).

---

## Highlights

### Read a Postgres outbox table (`type: postgres_outbox`)
A service that writes its events to an outbox table in its own database, in the same
transaction as its state change, can feed Kulyrax directly:

```yaml
sources:
  - type: postgres_outbox
    id: orders-outbox
    state_dir: ./.kulyrax/state
    config:
      url: ${OUTBOX_DATABASE_URL}
      table: public.outbox
      sequence_column: id
      columns:                       # defaults shown
        event_id: event_id
        event_type: event_type
        payload: payload             # json, jsonb or text
        metadata: metadata           # json / jsonb object, or ~ for none
        version: version             # integer, or ~ for always 1
      gap_grace_ms: 1000
      gap_timeout_ms: 10000
      watch_retention_ms: 3600000
      allow_unverified_sequence: false
```

- **Order** comes from `sequence_column` alone, which is also each event's
  `sequence`; never a timestamp or a database clock.
- **Read only.** Kulyrax runs `SELECT`s, never inserts, updates or deletes outbox
  rows, and keeps its position in its own checkpoint in `state_dir`.
- **Start-up checks** refuse, naming the problem: a missing table or column, a column
  of the wrong type, a sequence behind `sequence_column` without `INCREMENT 1` and
  `CACHE 1`, or a column with no sequence at all (unless `allow_unverified_sequence:
  true`, which gives up the check that values follow insert order).
- **Gaps.** A missing sequence value holds delivery. When a gap is first seen,
  Kulyrax records the snapshot's `xmax`; once the database's oldest running
  transaction is newer than that, no transaction that could still insert the
  missing rows is running, and the gap is skipped once it has also been held
  `gap_grace_ms` (default 1 s; it covers a producer that called `nextval()` before
  inserting, which that check cannot see). `gap_timeout_ms` is a
  backstop. Skipped values are watched for `watch_retention_ms` (at most 10,000); one
  that appears is delivered late, logged with its outcome, and counted.
- **`kulyrax sources`** shows each outbox's watched gaps, late rows, and late rows
  skipped.
- **One reader per source.** The source locks `<state_dir>/<id>.lock`; a second
  process on the same source stops at start-up.

Postgres 13 or newer. Registered by `kulyrax-backends` under the feature
`postgres-outbox` (on by default); the crate is `kulyrax-source-postgres`. Design and
trade-offs: [decision record](../docs/ledger/decisions/2026-11-24-postgres-outbox-source.md).

### Third-party sources
A `sources:` entry with a `type:` Kulyrax doesn't build in now resolves through a
factory registered on the runtime, as adapters always have:
`KulyraxRuntime::register_source_factory("my_source", my_crate::factory)`.

## Upgrading from 0.11

### Everyone
- Nothing to change in config. An unknown source `type:` used to fail parsing; it now
  fails at start-up with the registered types listed.

### Embedding `kulyrax-core`
- `SourceConfig` has a new variant, `Custom(CustomSourceConfig)`, and no longer
  derives `Eq` or `Deserialize` through serde's tag (it implements `Deserialize`
  itself). Exhaustive matches need the new variant.
- `SourceError` has a new variant, `Unavailable`.
- `pipeline::build_sources` takes the runtime's `SourceRegistry` and an `inspect`
  flag; `pipeline::list_sources` takes `register_backends` and returns
  `Vec<SourceStatus>` (id, committed position, details) instead of tuples.
- `EventSource` has two new methods with defaults: `on_resolved(event, report)`,
  called by the run loop for every event before `commit`, and `details()`, shown by
  `kulyrax sources`.
- New: `source::lock_source`, `runtime::{SourceRegistry, SourceBuildContext,
  SourceFactory}`, `KulyraxRuntime::{register_source_factory, source_registry}`.

## Known limitations
- Polling only; logical replication is not supported.
- A row whose transaction took its sequence value before it had a transaction id
  (`nextval()` called before the insert) and waits longer than `gap_grace_ms` to
  insert, or that outlasts `gap_timeout_ms`, can
  arrive after its gap was skipped. It is delivered late and judged by its
  sequence: if its entity has a newer event, it is skipped as stale.
- An unrelated long transaction on the producer's database holds gaps back until it
  ends or `gap_timeout_ms` passes.
- Kafka and Kinesis sources are still open.

# Kulyrax v0.7.0

## Status

Alpha — feature release covering **Phases 19–21**: a production-real Postgres SQL
backend, a technology-agnostic gRPC ingestion contract, and OSS release readiness
(licensing, CI, examples, docs).

---

## Highlights

### Postgres SQL backend (Phase 19)
- `AdapterConfig::Postgres` — a second SQL backend alongside SQLite, behind the same
  `SqlTxn` seam (`adapter/sql/exec.rs`) introduced in Phase 19.1 so dialect differences
  (placeholder style, `RETURNING`, upsert syntax) never leak into mapping code.
- Column-type introspection (Phase 19.3): a mapping's resolved JSON values are cast to
  the target column's actual Postgres type at write time, instead of relying on
  implicit driver coercion.
- `FOR UPDATE` row locking on the guard read (Phase 19.4) — Postgres is the first
  multi-writer-safe adapter; concurrent writers to the same entity serialize correctly
  instead of racing past `decide()`.
- `${ENV_VAR}` expansion in a Postgres adapter's `url` config, so connection strings
  don't need to be committed in plaintext.
- New transitive dependency: `postgres` pulls in `tokio` for `kulyrax-core` itself (the
  SQLite backend alone never needed it).

### gRPC ingestion contract (Phase 20)
- `proto/kulyrax/v1/ingest.proto` — a versioned, technology-agnostic contract:
  bidirectional `Stream(EventEnvelope) returns (stream Ack)`. Any `protoc`/`buf`-capable
  language can generate a producer against it.
- New `kulyrax-ingest` crate (the `tonic` server + a `GrpcSource` `EventSource` impl)
  and `kulyrax-client` crate (the reference Rust producer) — `tonic` stays isolated to
  `kulyrax-ingest`, so embedding `kulyrax-core` directly still doesn't pull in a gRPC
  stack.
- New `kulyrax ingest --config … --mappings … --listen tcp://host:port` subcommand.
- Stateless resume-from-ack: a producer persists the last `Ack.position` it saw and
  resumes from there after a disconnect; Kulyrax's guard-lane idempotency absorbs
  whatever the producer re-sends.
- Phase 21.6 adds a Unix-domain-socket listener (`--listen unix:/path/to.sock`) for
  same-host producers, alongside the existing `tcp://` form.

### OSS release readiness (Phase 21)
- Dual **MIT / Apache-2.0** licensing; `[workspace.package]` shared metadata
  (`rust-version = "1.88"`, repository, authors) across all four crates.
- GitHub Actions CI: cross-platform build/test/clippy/fmt matrix, a Postgres
  integration job, an MSRV check, and an examples job.
- Four runnable examples under [`examples/`](../examples/) covering the CLI, the
  Postgres backend, embedding `kulyrax-core` directly, and gRPC ingestion.
- New docs: [`docs/concepts.md`](../docs/concepts.md) (the mental model),
  [`docs/mapping-reference.md`](../docs/mapping-reference.md) (every mapping field),
  and [`proto/README.md`](../proto/README.md) (writing a non-Rust producer). The root
  `README.md` is rewritten around a sub-60-second quickstart.

## Behaviour changes — read before upgrading from v0.6.0

- **New config variant:** `adapters[].type: postgres` alongside `sqlite`, with its own
  `config.url` (supports `${ENV_VAR}` expansion). No change to existing `sqlite` configs.
- **New capability surface:** the Postgres adapter declares `write`, `upsert`, `delete`,
  and `transactions` — the same `requires_capabilities` vocabulary mappings already use
  against SQLite.
- **New CLI subcommand:** `kulyrax ingest`. No change to `run` / `sources` / `explain` /
  `dry-run` / `replay`.
- **`kulyrax-ingest` / `kulyrax-client` are new crates** — no API removed or changed on
  `kulyrax-core` or `kulyrax-cli`.
- **Crate metadata:** all four crates now carry `rust-version = "1.88"` (MSRV). No
  behavioral change, but a `cargo clippy` run enables `clippy::incompatible_msrv`, which
  will flag code using anything stabilized after 1.88.0.

## Non-Goals (this release)

- No Docker/Kubernetes/sidecar packaging.
- No Pro-tier modules (managed connectors, multi-node coordinator, encryption adapters, UI).
- No new engine features or adapters beyond the Phase 21.6 UDS listener.
- No benchmarks, no hosted docs site, no Windows named-pipe transport.
- `kulyrax-core` / `kulyrax-cli` are not yet published to crates.io under those names —
  both are already taken by an unrelated project on the registry. `kulyrax-ingest` and
  `kulyrax-client` are unclaimed. Not resolved in this release; tracked as a known
  blocker to an eventual `cargo install kulyrax-cli`.

Not intended for production use.

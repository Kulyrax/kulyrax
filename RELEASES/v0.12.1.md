# Kulyrax v0.12.1 (draft)

## Status

Alpha. **Security release.** Fixes
[GHSA-6chh-gx4c-448g](https://github.com/Kulyrax/kulyrax/security/advisories/GHSA-6chh-gx4c-448g):
the file-backed stores built file names from event data without encoding it.
Affected: every version up to and including 0.12.0. Fixed: 0.12.1.

Upgrade if you run the file-backed key-value, document or graph stores, or a
dead-letter directory, on events you do not fully control. The networked backends
had smaller, related gaps that are also closed (see [below](#networked-backends)).

Read [Upgrading from 0.12.0](#upgrading-from-0120) before you upgrade: a store that
holds files named from ids with uppercase letters or special characters must be
rebuilt.

---

## What was wrong

The file-backed stores turned an entity id (a key-value key, a document id, a graph
node id), taken from the event payload, straight into a file name:
`<root>/<namespace>/<key>.json`. A file name is not an opaque string, and an id was
able to:

- **leave the store root.** An id like `../../somewhere/x` wrote, and on delete
  removed, `.json` files (and guard files) outside the store, wherever the
  process could write. Anyone who can
  put an event on a source Kulyrax reads (a producer on the gRPC ingest endpoint, a
  writer to a watched directory or an outbox table) could do this.
- **merge two entities.** On a case-insensitive file system (Windows, macOS by
  default), `K` and `k` are one file. Their guard lanes overwrote each other, so
  after a restart an older event for one could be applied over a newer one.
- **fail every event for that entity.** Ids over 255 bytes, ids like `CON` or `nul`
  on Windows, and ids with a trailing `.` could not be written at all, or were
  written somewhere other than where they were read from.

Related gaps:

- **Namespace names reached the store's own files.** A key-value namespace named
  `wal` or `lock` put its guard files in `.conduit/wal/` or at `.conduit/lock`,
  where the batch log and the store lock live. Replaying the batch log or taking
  the lock then failed. Mapping names (namespaces, collections, labels, edge types)
  were not checked at all, so `../x` or `.conduit` also worked as one.
- **Dead-letter file names** took the source position as given. Over gRPC the
  producer chooses the position, so a position like `../../x` placed the
  dead-letter file outside `dlq_dir`.

## What changed

### File names are an injective, case-safe encoding of the id

Every id becomes a file name by one encoding:

- Ids made of lowercase ASCII letters, digits, `_`, `-`, `@` and `.` (not first or
  last) are used as they are, so `user-42` is still `user-42.json`.
- Every other byte becomes `^` followed by two lowercase hex digits: `K` is `^4b`,
  `../x` is `^2e.^2fx`. `^` is itself escaped, so no encoded name equals another
  id's plain name. Two different ids never get the same file name, even when the
  file system ignores case.
- A Windows device name (`con`, `nul`, `com1`, …) gets its first letter escaped.
- An id whose name would be longer than 200 bytes is named `^h<sha-256 of the id>`.
  Its guard file stores the full id, and a read checks it. If two ids ever shared a
  hash, the event fails instead of using the other id's guard lane.

This applies to key-value values and guards, documents and their guards, graph
nodes, edges (already hex-encoded, now hashed when long) and incidence files.

### The store's own files are out of reach

Key-value guards move from `.conduit/<namespace>/` to `.conduit/kv/<namespace>/`.
Mapping names are now checked, so no namespace can reach `.conduit/wal` or
`.conduit/lock`.

### Mapping names are checked at start-up

A key-value namespace, document collection, graph label or edge type used by a
file-backed store must be 1–64 bytes of ASCII letters, digits, `_` and `-`, and
must not be a Windows device name. Two names that differ only by case (`Users`
and `users`), or two adapters on one root that would write the same directory
(a key-value namespace and a document collection both named `users`), are refused
with an error that names both. Nothing is written before these checks pass.

### Dead-letter file names

The position in a dead-letter file name (`<event_id>.<position>.json`) is encoded
the same way, so it never leaves `dlq_dir`. Positions made only of ordinary
characters keep their names. Others are now escaped, so a script that builds these
names itself must escape them the same way.

### Networked backends

- **Elasticsearch**: a document id of `.` or `..` fails the event with
  `elasticsearch cannot address a document with id "..": it is a URL dot segment`.
  Before, such a request reached another endpoint (`/<index>/_doc/..` resolves to
  `/<index>/`) and failed with an unrelated error. Other ids were already
  percent-encoded and are unchanged.
- **Postgres, MySQL, SQLite**: table, column and primary-key names from the mapping
  are written into SQL unquoted. They must now be plain identifiers
  (`[A-Za-z_][A-Za-z0-9_]*`, the table optionally `schema.table`), checked before
  any statement runs. Values were always bound parameters and are unchanged.
- **Redis**: a namespace must be non-empty, contain no `:` and not start with
  `__kulyrax`. Otherwise its keys could meet another namespace's keys or the guard
  keys.
- **Neo4j**: labels and edge types must be non-empty and contain no backtick.
  Property values were always parameters and are unchanged.
- **MongoDB**: no change. Ids and collection names go to the driver as data.

## Upgrading from 0.12.0

On its first start, each file-backed store checks its directory once and records
that in `.conduit/layout/<kind>`:

1. **Key-value guards are moved** from `.conduit/<namespace>/` to
   `.conduit/kv/<namespace>/` under the same names. Every guard lane is kept, and
   a redelivered older event is still skipped as stale. If a guard exists at both
   the old and the new path, start-up is refused and both paths are named.
2. **Files this version would name differently are refused, never renamed.**
   If the store holds files named from ids with uppercase letters, `/` (a nested
   directory), a leading or trailing `.`, other special characters, or very long
   ids, start-up fails, names up to 20 of the paths, and says:

   > Rebuild the store: move it aside and project the full event history into an
   > empty directory

   Kulyrax does not rename these files for you. A renamed file under the wrong name
   is a lost guard lane, and a lost lane lets an older redelivery be applied. On a
   case-insensitive file system, two such ids may already share one file, and no
   rename can separate them.

   To rebuild: stop Kulyrax, move the store directory aside, point the adapter at
   an empty directory (or the old path once it is empty) and replay from the start
   of the event history (`kulyrax replay`, or reset the source's checkpoint). Keep
   the old directory until the new one is verified.
3. **Mapping names are checked** (see above). A mapping that used a name outside
   the plain set fails at start-up with an error that names it. Rename it, and
   rebuild that store, since the directory name changes.

Stores whose ids and names were already plain (lowercase letters, digits, `_`, `-`,
`@`, inner `.`) open unchanged, apart from the key-value guard move.

**Do not go back to 0.12.0 on a store 0.12.1 has opened.** 0.12.0 does not know
the new key-value guard path: it would find no guards and re-apply every event it
is given. If you must, move `.conduit/kv/<namespace>/` back to
`.conduit/<namespace>/` and delete `.conduit/layout/` first.
